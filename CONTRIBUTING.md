# Contributing to fxamacker/cbor

Thank you for contributing to this CBOR codec.

These guidelines reduce security risks, operational risks, and legal risks from unvetted AI-generated content, false positives, uncoordinated pull requests, and uncertain authorship.  Issues and pull requests that do not follow them may be closed.

## Security Vulnerabilities

Please do not open public issues or pull requests for security vulnerabilities.  Report them privately as described in the [Security Policy](https://github.com/fxamacker/cbor/blob/master/SECURITY.md).

## Prohibited Content

Please do not transmit personal data, secrets, nonpublic information, malicious code/links, or any data that could create regulatory compliance obligations, legal liabilities, or other risks for the recipient.

## Opening Issues

Before opening an issue, please ensure a human confirms it matters in real use.  Some AI-detected bugs only occur when AI-written reproducers use anti-patterns or settings that don't reflect real user apps in production environments.

You can open an issue from the [Issues page](https://github.com/fxamacker/cbor/issues), or create one using these links:

- [Open a bug report](https://github.com/fxamacker/cbor/issues/new?template=1-bug-report.yml)
- [Open a feature request](https://github.com/fxamacker/cbor/issues/new?template=2-feature-request.yml)

## Opening Pull Requests

Although contributors may use AI to improve their PR description (e.g., to improve grammar), all attestations must be made by a human (e.g., adding Signed-off-by lines to commits, certifying DCO 1.1, or confirming they personally reviewed each changed line).

To ensure work is well-coordinated, please comment on the related issue saying you plan to work on it, and wait for a maintainer to reply that you can proceed before opening a PR.  Even a one-line change can affect in-progress work, planned work, or ongoing maintenance (e.g., testing, fuzzing, and backward compatibility checks).  If no related issue exists, create one first.

Please follow the [Pull Request Template](https://github.com/fxamacker/cbor/blob/master/.github/pull_request_template.md), which lists requirements for coordination, AI usage disclosure, standards, compatibility, performance, and sign-off (DCO 1.1).
